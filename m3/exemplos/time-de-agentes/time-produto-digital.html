Time 03 · Construir com IA

Time de Produto Digital.

Ajuda quem constrói produtos digitais a dominar o Claude Code de ponta a ponta — do primeiro setup do projeto até automações avançadas, sem depender de um dev sênior "traduzindo" cada decisão. Cobre desde "como configurar" até "como escalar com vários agentes trabalhando em paralelo".

Quando usar: quando o PM/founder não-técnico está montando um produto com Claude Code e não sabe se aquilo que precisa é uma regra fixa, uma automação, um novo agente ou uma integração externa — o time diagnostica e aponta o especialista certo.

NÍVEL 1 Fundação do Projeto prepara o terreno — regras da casa e integração ao projeto
01
🛡️Guardião

Arquiteto de configuração — é quem escreve as "regras da casa" para o Claude Code (o que ele pode ler, editar, executar e onde pedir permissão).

Atua emCamadas de configuração (settings.json, CLAUDE.md, permissões, sandbox) — organiza o que é regra da empresa, do projeto ou pessoal.
Consulte quandoVocê quer garantir que o Claude não mexa em arquivo sensível, separar o padrão da empresa do pessoal, ou começar um projeto com permissões desenhadas antes de sair executando.

"Configuração é código. Permissão mínima por padrão. Comece negando tudo e libere só o necessário."

02
🏗️Alicerce

Integrador de projeto — pega um repositório qualquer (novo ou legado bagunçado) e encaixa o Claude Code nele sem quebrar o que já funciona.

Atua emMetodologia PAI (Personal AI Infrastructure) de Daniel Miessler + ciclo 7 fases: Observar → Pensar → Planejar → Construir → Executar → Verificar → Aprender.
Consulte quandoTrazendo o Claude Code para um projeto que já existe (com CI/CD, testes, hooks de git), montando estrutura do zero, ou precisa que ele entenda a "operação" do projeto sem se perder no meio da sessão.

"A estrutura importa mais que o modelo. Objetivo → Código → Terminal → Prompts → Agentes."

NÍVEL 2 Automação & Extensão constrói as capacidades personalizadas — hooks e skills
03
⚙️Gatilho

Arquiteta de automações determinísticas — monta as "regras automáticas" que disparam sozinhas em momentos-chave (antes de salvar arquivo, ao terminar uma tarefa, quando o Claude vai comprimir a memória).

Atua emOs 17 eventos do ciclo de vida do Claude Code (SessionStart, PreToolUse, PostToolUse, Stop, PreCompact e outros) — cada um vira uma oportunidade de encaixar automação.
Consulte quandoVocê quer que uma regra ACONTEÇA SEMPRE, sem depender do Claude "lembrar" (rodar teste antes de commit, bloquear comando perigoso, registrar log automático, injetar contexto no início da sessão).

"Determinístico vence probabilístico. Se tem que acontecer sempre, vira gatilho."

04
🔨Forja

Artesão de habilidades — cria as "skills" (habilidades reutilizáveis) e comandos personalizados (/comando) que viram os atalhos do seu dia a dia.

Atua emSpec-driven development (inspirado em BMAD Method) — todo workflow repetido vira uma skill com contrato claro de entrada e saída.
Consulte quandoPercebe que está copiando o mesmo prompt toda semana, quer transformar um processo repetitivo em comando de uma linha, ou empacotar seu conhecimento num plugin pra o time inteiro usar.

"Especificação antes do código. Toda habilidade é um contrato entre a intenção humana e a execução da IA."

NÍVEL 3 Escala & Ecossistema de agente sozinho a sistema — MCPs, multi-agent e novidades
05
🔌Conector

Integradora de ferramentas externas (MCPs) — pensa em quais "plugins" o Claude precisa pra conectar em serviços de fora (GitHub, Slack, banco de dados, APIs) sem inchar a memória dele.

Atua emEconomia da janela de contexto — cada ferramenta adicionada custa tokens; a arte é escolher o mínimo que desbloqueia o máximo (inspiração: Peter Steinberger).
Consulte quandoQuer conectar o Claude com Notion, Supabase, Gmail; está com sensação de "o Claude está lento e esquecendo coisas" (provavelmente MCPs demais); ou não sabe se usa MCP ou apenas o terminal.

"Menos é mais. Terminal primeiro, MCP quando necessário. Justifique cada adição."

06
🕸️Maestro

Maestro de múltiplos agentes — desenha times de agentes trabalhando em paralelo, cada um em seu contexto isolado, coordenados por uma topologia clara.

Atua emCinco topologias canônicas — Líder-trabalhadores, Pipeline, Enxame, Conselho, Vigia (inspiração: Kieran Klaassen + Reuven Cohen).
Consulte quandoUma tarefa é grande demais para um agente só, quer rodar várias explorações em paralelo (ex: pesquisar 5 concorrentes ao mesmo tempo), ou precisa de "revisor + construtor" trabalhando juntos.

"Topologia primeiro. Isolamento por padrão. Todo trabalho que se abre em paralelo precisa de um ponto de convergência definido."

07
🔭Radar

Sentinela do roadmap — acompanha tudo que a Anthropic lança no Claude Code e traduz em: "vale adotar já, vale testar com cuidado, ou é experimental demais".

Atua emFilosofia "plan-first" de Boris Cherny (criador do Claude Code) + Technology Radar (Adopt / Trial / Assess).
Consulte quandoQuer saber se uma feature nova (Agent Teams, Cowork, Fast Mode) já vale a pena adotar, precisa planejar migração, ou não tem certeza se o que está fazendo já foi resolvido nativamente numa versão recente.

"Planeje antes de codar. Otimize por custo de mudança confiável, não por custo de token."

Fricção

Tensões produtivas — o time discorda por design.

São escolhas de arquitetura que antes ficavam invisíveis dentro da cabeça de um dev sênior. Aqui elas viram pergunta explícita: menos ferramentas ou mais agentes? Regra rígida ou capacidade elástica? Planejar tudo ou reagir na hora?

Fluxo

O roteiro padrão pra levantar um projeto novo.

7 passos do primeiro setup até escala multi-agente. Nem todo projeto passa por todos — mas essa é a ordem que evita retrabalho depois.

Diferencial

O que muda pra quem NÃO é desenvolvedor.

Esse time troca "eu preciso aprender a programar para ter opinião" por "eu preciso aprender a orquestrar para ter controle". Cada especialista representa uma decisão de arquitetura que antes ficava invisível dentro da cabeça de um dev sênior — e agora vira pergunta explícita e didática: isso deveria ser uma regra automática ou uma habilidade sob demanda? Deveria estar na configuração da casa ou no comando do dia? Vale adicionar mais uma ferramenta externa ou o terminal já resolve? O PM aprende a pensar como TechLead — não porque precise escrever código, mas porque passa a fazer as perguntas certas na hora certa, no vocabulário que o time técnico respeita. É o passo entre "usar IA" e "arquitetar sistemas com IA".
