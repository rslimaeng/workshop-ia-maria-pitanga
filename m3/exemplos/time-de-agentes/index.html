Extra do M3 · O nível seguinte

Criando seu time de IA.

No M3 você montou um agente. Aqui você vê o nível seguinte: em vez de um assistente, um time deles. Um orquestrador escuta o que você precisa, escolhe o especialista certo e responde na voz dele. Roda no mesmo Claude Projects que você já usou — muda só o desenho.

Formato Só didático · nada pra baixar 3 times de exemplo Roda em Claude Projects
Passo 1 · Entender o problema

Chat solto responde no meio-termo.

Uma IA sem orientação de papel entrega uma média — nem tão profunda quanto o especialista, nem tão prática quanto o executor. Time orquestrado resolve isso: cada pergunta cai no lugar certo.

Chat solto
Um assistente que tenta ser bom em tudo
"Como devo posicionar minha marca de açaí no Nordeste?"

A IA responde genérico e polido: fala de público-alvo, proposta de valor, diferencial. Serve pra estudante de MBA. Não serve pra reunião de segunda com o time de marketing.

Time orquestrado
Um time onde cada especialista tem escopo
Mesma pergunta.
Orquestrador identifica: posicionamento → ativa Al Ries.

A resposta vem na voz do Ries: "marketing é batalha de percepção, não produto. Qual palavra você quer possuir na mente do consumidor de açaí no Nordeste?" — provocação real, framework definido, próximo passo claro.

Passo 2 · Entender a arquitetura

Um time de agentes tem 3 peças fixas.

Não é mágica, não é multi-model. É engenharia de prompt bem feita em 3 camadas que trabalham juntas dentro do mesmo Claude Project (ou Gem, ou Custom GPT).

01
O Orquestrador

Um system prompt que não responde nada por conta própria. Sua única função é ler a pergunta, escolher o especialista certo e emprestar a voz dele pra resposta.

02
A Base de Especialistas

Um arquivo .md anexado ao Project. Define cada agente: nome, escopo, tom, framework, restrições. É o "contrato" que o orquestrador consulta antes de responder qualquer coisa.

03
A Ativação de Persona

A regra que muda tudo: o orquestrador não descreve o especialista, ele vira o especialista. Você recebe a resposta como se falasse direto com o Al Ries, não com uma IA "canalizando" o Al Ries.

Passo 3 · Ver o código

O orquestrador cabe em uma página.

Não precisa de framework, agente autônomo, MCP nada. É um system prompt de ~100 linhas que define 4 blocos essenciais.

orquestrador.md · 100 linhas system prompt
# IDENTIDADE E FUNÇÃO Você é um Orquestrador de Agentes. Seu papel não é responder diretamente — é identificar qual agente definido no arquivo base deve responder, ativar aquela persona e entregar a resposta como se fosse esse agente. # PROTOCOLO OBRIGATÓRIO Passo 1 — Leia o arquivo base Passo 2 — Selecione o agente correto Passo 3 — Incorpore a persona Passo 4 — Complemente quando necessário # REGRAS DE OPERAÇÃO 1. O arquivo base é lei 2. Nunca misture agentes sem avisar 3. Identifique o agente ativo no início 4. Recuse na persona, nunca como sistema 5. Sem voz própria não autorizada # COMANDOS DE CONTROLE /agentes → lista todos disponíveis /ativar → força um específico /quem → qual está ativo agora /geral → desliga persona

Identidade

Deixa claro que o orquestrador não é o protagonista — é o roteador. Empresta voz, não tem voz.

Protocolo em 4 passos

Sequência fixa: lê base → escolhe agente → vira o agente → complementa se precisar. Toda pergunta passa por aqui.

Regras de operação

Os limites que impedem o modelo de "voltar ao genérico" no meio da resposta. A regra 4 é crucial: recusa na persona, não como sistema.

Comandos de controle

Você pode forçar troca de agente com /ativar Ries ou perguntar quem está ativo com /quem. UX simples.

Passo 4 · Ver funcionando

O fluxo em 4 passos, invisível pra você.

Você digita a pergunta. Nos bastidores, o orquestrador executa esses 4 passos em segundos — e você só vê a resposta final na voz certa.

Você
01 · Pergunta
"Como estruturo o lançamento do meu produto?"
Uma pergunta comum, ambígua entre estratégia, marketing, execução.
Orquestrador
02 · Roteia
"Decisão estratégica de lançamento → Estrategista lidera."
Consulta o arquivo base, identifica que o Estrategista é dominante aqui.
Especialista
03 · Incorpora
"Assumo a voz do Estrategista, tom analítico, framework definido."
Não descreve o especialista — vira o especialista, seguindo tom e restrições do arquivo.
Você
04 · Recebe
Resposta na voz certa, com framework, provocação e próximo passo.
Você conversa com o especialista. O orquestrador some no meio da resposta.

Passo 6 · Discernimento

Não é sempre que faz sentido.

Time de agentes virou moda. A parte honesta: ele é útil pra alguns problemas e overkill pra outros. Um bom prompt ainda vence time mal montado.

Faz sentido quando
  • Sua decisão precisa de 3+ óticas diferentes (estratégia + marca + finanças, por exemplo)
  • Você quer consistência de tom em respostas repetidas (todo prompt de marca vira StoryBrand)
  • O problema tem tensões produtivas — Ries vs Sharp, marca vs performance, produto vs pessoa
  • Você repete o mesmo tipo de análise toda semana e o setup vale a pena
  • Você quer escapar do "meio-termo" da IA genérica e ter opinião de verdade
NÃO faz sentido quando
  • Sua pergunta é simples e direta (resumir texto, traduzir, formatar)
  • Você ainda não domina prompt básico — comece pelo PCTFL+ do M1, não pelo time
  • Você quer time porque parece impressionante — se um prompt resolve, use um prompt
  • Seus "especialistas" são vagos — se você não consegue definir escopo, o orquestrador vai patinar
  • Você não vai usar 3x/semana — o custo de manter o arquivo base não paga
Passo 7 · Colocar em prática

Como montar o seu time — 5 passos.

Um time funcional roda no Claude Projects — o mesmo que você usou no caso-âncora do M3 — em uma tarde de trabalho. O que dá trabalho é escolher os especialistas certos — não o código.

  1. Define o problema recorrente que o time resolve

    Não monta time "geral". Monta time pra uma tarefa que você repete: análise de marca semanal, revisão de copy, decisão de investimento, code review. Sem problema claro, o time vira teatro.

  2. Lista 5 a 15 especialistas com escopos que não se sobrepõem

    Cada um resolve um pedaço diferente. Se dois especialistas fazem a mesma coisa, um sobra. Pensa em tensões produtivas também: Ries (foco) × Sharp (alcance) é ouro — força opinião.

  3. Escreve o orquestrador (system prompt)

    Segue a estrutura padrão: identidade + protocolo de 4 passos + regras de operação + comandos. Cola no campo System instructions do Claude Project.

  4. Monta o arquivo base .md com todos os agentes

    Um bloco por agente: nome, credencial, tom, framework, quando ativar, exemplos, restrições. Anexa como knowledge no Project. Esse é o "contrato" que o orquestrador consulta.

  5. Testa com 10 perguntas reais e ajusta

    Faz perguntas que já apareceram no seu dia. Se o orquestrador escolheu errado, o problema tá no arquivo base (escopo mal definido). Ajusta e testa de novo. Em 2-3 rodadas o time tá pronto.
